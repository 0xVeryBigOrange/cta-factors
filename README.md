# CTA 多因子看板

加密货币和美股的多因子、多周期多空看板。每个因子在每个周期上给出多头、空头或中性，以及 [-1, 1] 的强度；同一因子可以在 5 分钟上偏多、在 1 小时上偏空。页面是简体中文。

在线地址：[https://0xverybigorange.github.io/cta-factors/](https://0xverybigorange.github.io/cta-factors/)

作者 / 关注 X：[@0xVeryBigOrange](https://x.com/0xVeryBigOrange)

本站内容只供信息展示和学习，不构成投资建议或交易依据。

## 功能

- 自选列表保存在浏览器 `localStorage`。可以搜索、添加、删除，并按全部 / 加密 / 美股筛选。
- 默认加密：BTC、ETH、SOL、BNB、XRP、DOGE、ADA、AVAX、LINK、DOT。也可以输入其他 USDT 现货代码。
- 默认美股：AAPL、NVDA、TSLA、MSFT、AMZN、META、GOOGL、SPY、QQQ。内置列表里还有一批大盘股和 ETF，任意美股代码也可以添加。
- 周期：5 分、15 分、30 分、1 小时、4 小时、日线、周线。数据源不支持或 K 线不够时，格子显示为不可用，而不是编造信号。
- 因子矩阵：行是分组后的因子，列是周期。绿色为多，红色为空，灰色为中性，颜色深浅表示强度。
- 综合概率：每个周期把全部因子合成一个多头概率。
- 自选总览：全部代码 × 全部周期，可按强多（≥65%）、强空（≤35%）、中性筛选，并可排序。
- 加密在 Binance 公共 WebSocket 可用时实时推送 K 线，否则轮询。页面显示最近刷新时间和最新 K 线时间。美股若使用构建时的 Yahoo 缓存，还会显示该缓存的抓取时间，并在缓存过旧时提示。

## 数据源与局限

### 加密货币

K 线按下面的顺序尝试，谁先返回足够长度且间隔正确的数据就用谁：

1. **Binance 公共行情** `https://data-api.binance.vision`（现货 K 线，响应带 `Access-Control-Allow-Origin: *`，浏览器可直接访问）。实时推送使用 `wss://data-stream.binance.vision`。
2. OKX 现货 K 线（会按请求来源回显 CORS）。
3. Gate.io 现货。
4. Bitget 现货。
5. Kraken。
6. Coinbase（没有 30 分、4 小时、周线；历史也更短）。
7. CoinGecko OHLC（没有成交量，粒度粗，只适合作为日线 / 4 小时级别的最后兜底）。

`api.binance.com` 和 `fapi.binance.com` 在部分网络会返回 451，因此没有把它们当作主源。Bybit 在部分地区也会被拦住，所以没有放进回退链。

衍生品只对加密显示，来自 **Gate.io** 的公开合约统计、资金费率历史和标记价 / 指数价。Gate 失败时改用 **Bitget** 的资金费率和账户多空比；Bitget 这条路径没有持仓量历史，持仓量因子会空着。小币如果没有 USDT 永续，整组衍生品为空。

这些读数不是每个周期都有原生 K 线：

- 资金费率大约 8 小时一条。短周期至少看最近 8 小时，长周期看更长的平均。
- 持仓量和多空比用 5 分、1 小时、日线历史拼在一起，再按当前周期的回看窗口取变化。窗口盖不住就留空。
- 基差是实时快照，七个周期是同一个数。

### 美股

Yahoo Finance 图表接口 `query1.finance.yahoo.com/v8/finance/chart` **没有浏览器 CORS**，页面不能直接请求。本仓库用两种互补方式：

1. **GitHub Actions 预取（主路径）**。`Deploy GitHub Pages` 在推送到 `main`、手动触发，以及每小时的定时任务里，用 Yahoo 拉 `src/data/universe.json` 里的美股，写成 `public/data/equities/<SYMBOL>.json`，再和静态站一起发布。4 小时没有原生周期，由 1 小时 K 线按 UTC 时间桶聚合。价格是图表接口的前复权（拆分已调整）OHLC，没有再做股息调整。每次 Yahoo 请求最多等 20 秒。429、500、502、503、504 和网络中断会短暂重试，超时则换更短的区间。某个周期没拉到时，用站点上一次发布的 JSON 把缺的周期补上，避免一次失败就把这个代码从页面上拿掉。收盘后 Yahoo 常常把当日收盘价留空，并在短周期末尾多给一根成交量为 0 的报价柱；周线也会把最新一个交易日拆到收盘时刻。写入缓存和页面读取时都会补上收盘价、去掉这根报价柱，并把拆出来的交易日并回当周。
2. **腾讯行情（浏览器补齐）**。`web.ifzq.gtimg.cn` 和 `qt.gtimg.cn` 允许跨域。已缓存的代码用它刷新报价；还没被 Actions 收录的代码，用它提供日线和周线。腾讯这条线目前拿不到可用的美股分钟 K，所以自定义代码的 5 分到 4 小时会标成不可用。行情可能延迟，休市时显示最近收盘。

定时任务由 GitHub 调度，设为每小时第 17 分钟。平台会推迟并丢掉一部分触发，实际间隔仍然会长于 1 小时。2026 年对约 200 个每小时工作流的统计里，整点和其它分钟的延迟差不多，实际大约每天 8 次；比这更密的 cron 也不会多跑几次，所以没有改分钟，也没有在同一小时再叠一条。本仓库原先每 2 小时一条，2026-11-22 到 11-24 大约每天只跑 3 次。抓取脚本本身每次大约一分钟就能跑完。两次发布之间，因子用的是上一次缓存，报价可以比 K 线更新。选中美股时，页面会标出这份 K 线缓存的时间。常规交易时段里缓存超过 4 小时、开盘后盘中 K 线仍停在上一交易日，或缓存早于最近一个工作日收盘（收盘后留出约 90 分钟），都会提示因子可能滞后。这里的交易时段是纽约时间周一到周五 09:30–16:00，不单独处理节假日。某个周期这次没拉到时，会沿用上一份该周期的抓取时间，避免只补上日线就把整份缓存标成新的。

本地开发时，如果还没有 JSON 缓存，Vite 会把 `/yahoo` 代理到 Yahoo，这样任意代码也能算出全部周期。Yahoo 失败时改用腾讯的日线和周线，5 分到 4 小时标成不可用。`npm run fetch-equities` 可以预先生成缓存。只拉一部分代码：`ONLY=AAPL,SPY npm run fetch-equities`。

### 频率限制

每个数据源有自己的请求间隔。单次请求超过 12 秒记为超时，立刻换下一个源，不再一直等。K 线按周期缓存（5 分约 20 秒，日线约 5 分钟），自选里当前代码优先加载，其余代码先加载日线和 1 小时。超时、断网、403、429、451 或 5xx 会把该源冷却约 3 分钟。刷新失败时，已经显示出来的 K 线和衍生品留在页面上，刷新时间停在上一次成功。

## 综合概率

1. 每个因子先把原始信号除以实现波动，再封顶到 [-1, 1]。正为多，负为空。接近 0 的格子显示为中性，但数值仍参与平均，不再被硬阈值清成 0。
2. EWMAC 用 Carver《Systematic Trading》的刻度：波动调整后的均线差放到「常态大约 10、上限 ±20」，界面再除以 20。其他波动调整因子用「大约 2 倍波动对应 ±1」。
3. 类别内部做加权平均。打开「用历史 IC 加权」时，权重 = 0.6 + 0.4 × clamp(IC / 0.08, -1, 1)，且不低于 0.2。样本少于 12 或没有 IC 时权重为 1。IC 是信号对随后 4 根 K 线收益的相关系数，命中率是方向一致的比例。样本大约 16 个点，只覆盖手头这截历史。
4. 六个类别再等权，得到原始分。因子多的类别不会压过因子少的类别。缺数据的因子跳过；整类都没有数据时，这一类退出。
5. 原始分乘以分散乘数。类别之间用先验相关 0.35，负相关按 0 处理。乘数 = min(2.5, sqrt(N / (1 + (N − 1) × 0.35)))。这是 Carver 的 forecast diversification multiplier。乘完后仍封顶在 ±1。
6. 多头概率 = 1 / (1 + e^(−3S))。S = 0 时为 50%，S = 1 时约 95%，S = −1 时约 5%。

自选总览和侧栏日线概率使用同一套类别等权和分散乘数，但不对每个代码重算 IC。这是因子投票的映射，不是未来涨跌的胜率。

对照时用过、但没有单独做成新格子的材料还有 Schmeling, Schrimpf and Todorov 的 BIS Crypto Carry：资金费率水平因子仍按做多成本反向解释。价值因子需要基本面，当前数据里没有，所以没有做横截面价值。

已改写的原有因子使用这些出处：

- Levine and Pedersen (2016) Which Trend Is Your Friend：波动率标准化后，均线交叉与时序动量是同一类信号。
- Baltas and Kosowski 的趋势信号与 Carver 的波动率标准化一致：斜率先除以波动，再封顶。
- Appel 的 MACD。缩放方式对齐 Carver：先做波动率标准化，再用上限代替硬阈值。
- Moskowitz, Ooi, Pedersen (2012) 用波动率标准化收益描述趋势强度，这里用回归斜率代替简单收益。
- Moskowitz, Ooi, Pedersen (2012) Time Series Momentum：方向看过去收益的符号，幅度用实现波动标准化。
- Hurst, Ooi, Pedersen (2017) A Century of Evidence on Trend-Following Investing：多个回看速度一起用。
- Larry Connors 的 RSI(2)。这里把极端阈值改成封顶，避免只在极少样本上突然翻转。

## 本地开发

```bash
npm ci
npm test
npm run fetch-equities
npm run dev
```

开发服务器是 `http://localhost:5173/`。`npm run build && npm run preview` 用和 GitHub Pages 相同的相对路径检查构建结果。

`.github/workflows/pages.yml` 在推送到 `main` 时测试、抓取美股缓存、构建，并用 `actions/configure-pages`、`actions/upload-pages-artifact`、`actions/deploy-pages` 发布。Pages 已经用 GitHub Actions 发布。工作流权限只有 contents、pages 和 id-token。

页面地址：`https://0xverybigorange.github.io/cta-factors/`。

`.github/workflows/ci.yml` 在 pull request 上运行测试和构建，不访问外网。
